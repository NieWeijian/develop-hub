# RK UVC 固件版本检查

这是能够调用真实 RV1126B/RMSL321 UVC 控制工具的只读用例包，验证范围是模组序列号与设备自报版本。它不执行烧录，不证明设备二进制与某个镜像相同，也不把主机模拟结果当作硬件结论。

将此目录内的 `manifest.json`、`run.py` 和本文件放在 ZIP 根目录后，从新平台导入并明确授权发布。参数 `expected_version` 没有默认值，必须填写完整版本令牌，例如 `factory-V2.1.0`。包含更长令牌的 `factory-V2.10` 不会匹配 `factory-V2.1`。

执行节点所需的 Python、UVC 控制工具和设备适配器由平台维护人员部署。普通用户在“设备与环境”中选择已部署的 RMSL321 测试台，填写或选择 CPU 序列号，无需输入命令、工具路径或 SHA-256。

平台安装入口为 `scripts/provision-rmsl321.py`，说明见 `docs/testing-platform-contract.md`。安装器使用运营者确认来源的控制工具，自动记录摘要和设备能力 `uvc.control.version.v1`，通过控制端的私有测试台注册表供平台使用。控制工具二进制不随示例分发。

驱动的 `inspect` 只调用 `get-cpu-serial` 和 `get-version`。独立 `deploy` 分支检查 RV1126B 芯片及固件清单，清单必须恰好包含 `oem.img`、`system.img`、`boot.img`。BoardConfig 仅用于记录，不参与目标版型匹配判定；方案需填写完整预期固件版本。

部署先读取 CPU 序列号和当前槽位，绑定物理 USB 口，仅写入对侧槽位。每个分区须确认传输完成，最后重新核对同一设备、槽位和完整版本令牌。部署行为已用替身设备测试，尚需在目标硬件上验收；不要把它登记为其他 RK 板型的通用烧录器。

用例运行前校验已登记工具摘要，读版本前后分别检查物理 USB 身份和 CPU 序列号，保存结构化断言及原始输出。错误工具、目标缺失/重复、热插拔身份变化、非零退出或空输出均不能形成通过结论。

本仓库的驱动/用例测试使用替身设备和替身工具结果，不执行实际烧录或 SDK 编译；真机验收需要连接节点上的真实模组后从“设备当前固件”方案执行。

# RGB + Depth 数据流质量

当前用例：STREAM-RGB-DEPTH。RGB 默认 **640×540 NV12 @10 fps**；Depth 默认 640×352 @10 fps，主机 V4L2 使用 YUYV 容器承载 16 位深度，不将它描述成 RGB YUYV 图像。只枚举和打开锁定 CPU 序列号/USB 端口的 RGB、Depth，不打开 IR。

## 预热与计时

1. 保存原设备模式，切换 rgb+depth。
2. 开启两路流，默认至少预热 10 秒；每路连续 3 个完整 1 秒窗口的有效帧率在请求 FPS ±20% 内才就绪。120 秒未稳定报执行异常。此条件用于排除启动阶段，不等于最终性能验收阈值。
3. 两路都就绪后执行一次 time-sync；再丢弃 3 秒数据让缓冲和时间戳稳定，然后两路以同一个主机单调时钟时刻开始正式计时。
4. duration_seconds 仅指正式测试时间，默认 18000 秒（5 小时），可配置 1～86400 秒。预热不计入，正式第一窗从统一起点完整统计；最后不足 10 秒的窗口按实际长度计算。
5. 结束关流，重启清除本测试写入的时间同步偏移，恢复原设备模式。不保证恢复测试前由其他主机设置的时钟偏移，当前 tools 缺少可直接保存/恢复该偏移的接口。

## 指标定义

- FPS：有效接收帧数/正式测量秒数，另存每 10 秒窗口 FPS。
- 传输丢帧：V4L2 buffer sequence 的前进缺口；处理 uint32 回绕，回退/重复单独记录，不累计成巨量丢帧。丢帧率=缺口/(收到帧+缺口)。这不能证明固件内部及 USB 全链路所有丢帧；源帧序号跳号只记录诊断，不直接当作传输丢帧。
- 延时：time-sync 后，主机 dequeue 单调时间减去帧头时间戳。记录最小/最大/均值/标准差及同步调用耗时。它是估算值，包含单向同步偏差及长时钟漂移，当前接口无法给出可靠精度界限。不是曝光开始到显示的精确端到端延时。
- 抖动：接收帧间隔标准差、估算延时标准差，单位 ms。帧间隔另存均值/最大/最小。
- 无性能阈值时，仅判完整运行、有效取流和数据基本有效；不声称性能达标。错误帧、无效帧、坏时间戳、提前结束或超出默认 5 秒无帧超时报错。

## 参数示例

```json
{
  "duration_seconds": 18000,
  "warmup_seconds": 10,
  "rgb_width": 640,
  "rgb_height": 540,
  "depth_width": 640,
  "depth_height": 352,
  "fps": 10,
  "stall_timeout_seconds": 5,
  "thresholds": {}
}
```

thresholds 分 rgb、depth，允许字段：min_fps、max_transport_drop_percent、max_latency_mean_ms、max_latency_max_ms、max_interval_jitter_ms、max_latency_jitter_ms。默认全不设置。latency 阈值针对上述估算值；出现负延时不得判定该阈值通过。

## 留存与实现边界

每帧主机时间、V4L2 序号、源序号、设备时间戳、有效性和驱动错误标志写入 CSV，每 50000 帧拆分文件，防止单个附件过大。保存预热诊断、配置、同步耗时、汇总指标、窗口 FPS；失败时保留已有原始数据及可生成的部分统计。Hub 结束后校验 SHA 并提供下载。

采集程序为 Hub 自有主机辅助工具，不实现新的固件控制协议。由 3588 GNU C++ 构建，链接已固化 tools 包的 V4L2 helper 源码；控制仍调用固件 uvc_host_ctl。测试包冻结辅助程序 SHA。

已做软件统计/参数回归、ARM64 编译验证；未新建轮次、未开流长测。真实固件上的时间戳同步效果、5 小时运行表现需由后续真机轮次验证。

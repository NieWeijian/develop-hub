# 三类测试流程设计草案

日期：2026-09-29。本文为设计建议，不表示已实现调度或发布验证。

## 当前基础

已有 TestProduct、TestPoint（Gerrit Change/Patch Set）、TestBench、TestRound，以及用例定义、工具能力校验、固定工具包、执行证据和人工结果归类。developer_tests.py 支持直接测试当前模组固件；常规 TestRound 支持编译、交付、烧录、执行与恢复。快速测试当前只观察设备报告的版本，不能据此证明其固件二进制等于某个发布包。

## 共用执行层，三个入口

| 入口 | 用户选择 | 固件来源 | 产出 |
| --- | --- | --- | --- |
| 快速测试 | 测试台、模组、用例和参数 | 模组当前固件；跳过编译烧录 | 单轮用例结果与证据 |
| 常规测试 | Gerrit 来源、时间、用例模板、测试台 | 调度时解析并冻结代码，再编译烧录 | 每次调度的轮次及版本趋势 |
| 发布验证 | 候选固件、验证清单、配置要求 | 一次构建/导入后锁定的固件包 | 跨轮次覆盖矩阵、缺项与最终验证报告 |

TestRound 继续表示一次执行。新增显式 origin（quick/scheduled/release/manual）、plan_id、candidate_id，替代靠 developer_mode 等快照字段推断业务类型。三类流程复用执行器、资源锁、能力检查、恢复逻辑及证据存储。

## 定时测试计划

新增 TestSchedule，保存产品、来源策略、分支或明确 Patch Set 规则、时区和时间、用例/参数模板、工具策略、测试台与启停状态。必须明确拉取已合入分支 HEAD，还是特定审核中 Change；不能含糊地选择“最新 Gerrit”。

每次触发生成持久化 ScheduleRun，冻结实际 commit、构建配置、tools SHA、用例代码和参数后再创建轮次。以 schedule_id + scheduled_time 唯一键防重复，保存 last/next fire time，服务重启后可恢复；默认不补跑堆积的历史触发。同计划上一轮未完成则记录跳过原因；不同计划共享测试台通过资源队列互斥。版本未变时是否跳过由计划配置。构建失败、台架离线、能力不支持与模组断言失败分别统计。调度器应属于 Hub 服务，不依赖当前对话或 Codex 定时任务。

## 发布验证计划

新增 ReleaseCandidate（候选固件）：产品、版本名、源码 commit/提交说明、构建配置、镜像集合及 SHA-256。一个版本可以有 RC1、RC2；任何镜像内容变化都创建新候选。编译/导入一次，后续补测复用固定镜像，不能每轮重新编译后只按同一 commit 认作同一固件。

新增 ReleaseValidationPlan / ReleaseRequirement：冻结当时的全量适用用例、定义与代码摘要、参数/阈值、tools 版本、硬件/模组数量要求，以及自动/人工/半自动执行方式。覆盖单位是“用例 + 必需配置”，不是仅一个用例名称。清单冻结后仍可增补，但需新清单修订及差异记录，不能静默改变分母。六个特殊场景先以待定义项展示；未定义/未实现仍是验证缺口，不能因为不可执行而从全量清单中消失。

新增 RequirementEvidence：将某轮某用例结果绑定到清单项，记录版本身份核验、证据、操作者与时间。可以多轮补测或重测失败项。默认采用同候选、同清单要求下最新一次有效完成结果；旧失败保留，后续失败不能被更早的通过覆盖。新执行仍在运行、阻塞、中断或错误时展示待处理状态，不以旧通过显示全绿。人工修正保留机器原始结果、修改人、原因和时间；手工测试记录步骤版本与必要证据。

快速/常规测试结果只有在固件身份、用例版本、参数、环境及 tools 与清单匹配时才允许引用，默认不自动认领。设备自报版本字符串不足以匹配发布二进制；必须有受控烧录链路/可验证固件摘要，否则只作参考。

状态区分：未测、运行中、通过、失败、阻塞、错误/中断、待定义、结果待更新。缺少接口或工装属于阻塞，不属于模组测试失败，也不算通过。默认全量要求所有适用项通过；如确实不适用，应有显式理由和审核记录，不能以“跳过”替代通过。未覆盖或有失败时不能标记验证完成。

最终冻结验证报告：候选固件 SHA、清单修订、每项采用的证据、历史失败与修正记录。验证完成与实际发布是不同动作，本阶段不新增自动发布。

## 前端组织

测试工作台三个入口：快速测试、常规测试、发布验证。共用用例库、测试台和历史轮次。轮次列表标识来源。

发布验证列表以版本为中心，显示通过/应测数量以及未测、失败、阻塞、待定义数量。详情顶部显示版本名与提交说明，接着是按场景分组的覆盖矩阵；每行显示用例、要求配置、当前结果、关联轮次及图片/日志入口。提供运行未测项、重测失败项、补录人工结果。编译烧录时间线仍在轮次详情，不挤占覆盖总览。

## 实施顺序

1. 特殊场景目录占位（本次完成）。
2. 固件候选实体、独立构建产物身份、每用例执行记录、轮次来源；数据库变更通过迁移。
3. 发布验证清单与覆盖矩阵、补测/人工证据/结果修正审计。
4. 定时计划、持久化调度记录、互斥队列与版本趋势；复用以上执行及身份链路。

关键验收包括：新 RC 不继承旧通过；缺接口保持阻塞；未实现特殊项保留缺口；跨轮补测覆盖正确；同名版本不同镜像不混用；失败重测不删除历史；调度重启不重复派发；同测试台不并发抢占；变更用例或参数使不兼容证据失效。

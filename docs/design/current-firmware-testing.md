# 当前固件快速测试与主机抓图

> 后续修订：以 [切换用例修订](switching-scope-revision.md) 为当前范围；下文的旧轮次结果保留为历史记录。


Develop Hub 负责 testcase、3588 取流抓图、证据归档、结果分类；固件团队负责 `uvc_host_ctl` 控制命令及其协议。抓图直接从 3588 收到的 UVC 帧取得，无须在模组内部 dump，也无须新增固件 dump 命令。

## 使用

新建测试轮次，勾选“开发者快速测试”，选择 3588、当前在线模组和用例，点击“测试当前固件”。不要求 Gerrit 测试点，不构建、不进入 DFU、不烧录。切换设备模式或算法分辨率本身仍会按现有 tools 行为重启模组。

配置保存当前完整固件版本、CPU 序列号、物理 USB 端口、所选用例及测试包 SHA-256。3588 执行前验证三项设备身份及测试包；重启后重新枚举视频节点并验证设备。开发模式与烧录模式使用独立通过条件，不把跳过烧录伪装为烧录成功。

## 已实现用例

独立覆盖旋转、RGB BTNR、IR BTNR、投影仪、算法 async/iter/fps/model_type/denoise/full_size/uncertain/discontinue/uncertain_delta、设备模式、分辨率共 15 项。分辨率项覆盖 640x352/512x448 算法档位与设备枚举的 RGB 分辨率。未遍历 USB profile。

每个状态保存配置回读、真实 XU 收发、连续有效帧、原始帧、PNG 预览及帧元数据。默认取样帧率 10fps；稳定要求至少连续 12 帧及至少 1 秒，等待上限 50 秒。这是切换后的有效取流检查，不代替五小时数据质量测试，不自动断言图像视觉效果或算法数值效果。

RGB 按枚举的 NV12 格式转换；Depth 的 YUYV 是传输格式标签，载荷按小端 uint16 深度毫米渲染（固定 100–1500mm 色标，0 为黑色）；IR 按双目 Y0/UV0/Y1/UV1 布局展示。原始帧保持不变，仅 PNG 屏蔽覆盖在像素上的帧头。不同流的取样不承诺同步配对。

BTNR 分别检查开流后的配置应用情况、持续开流中的开/关切换；初始状态不一致仍保留失败，继续采集后续状态。投影仪 enable=2 是命令邮箱空闲，不能作为物理灯状态 getter；检查命令消费并保留开/关图片，关流释放投影仪资源。

所有会改参数的用例保存原值并在 finally 恢复，模式重启后再次绑定相同设备；恢复失败停止后续用例。未实现自动断电或强杀后的模组状态恢复，此类中断需根据原始参数和日志处理，不自动重跑或烧录。

## 留存与版本

本地源码：`bench/test-cases/`、`bench/switch_runtime.py`、`bench/host_capture.cpp`、`bench/frame_images.py`。ARM64 主机采样器可在 3588 运行 `bench/build_host_capture.sh` 构建，复用已冻结的固件 tools V4L2 辅助源码，不改变固件协议。

175 的 `evidence/TEST-xxxxxx/` 保存轮次配置、快速模式精确测试包副本和用例证据；3588 的 `jobs/TEST-xxxxxx/cases/<code>/attempt-001/` 保留原件。结束后回传并验证每个声明附件的大小和 SHA-256；图片接口只开放结果清单中的附件。用例源码纳入本地 Git，Git bundle 另备份到 Windows。

图片仅用于展示结果。通过/失败人工调整继续在轮次用例行进行，保存修改人、理由及修订历史，原自动结果不改写。

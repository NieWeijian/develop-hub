## 2. 已确认的接入缺口

1. 当前 stream 不解析 migration 脚本使用的 --duration/--require-header/--require-exposure；未知参数会被忽略，且主循环正常退出返回 0。不能依此执行严格帧头判定，duration 也不能保证生效。
2. imu 正常结束返回 0，不等于频率、丢样和时间戳指标满足产品要求。
3. single runner 仍有 8fps 判定；CICD 文档要求按 RK3572 首轮基线固化阈值，不能沿用为正式量产标准。
4. 长短套件包含模式归一化、重启、参数写入和可选 OTA，不应作为不可拆解的单个基本用例直接运行。
5. latency 脚本有旧工具默认路径和固定 /tmp 日志路径；平台要使用任务独占路径与明确目标。
6. 文档与源码存在漂移；03-测试结果.md 的硬件结果为 NOT RUN，静态 FAIL 必须保存为历史静态发现，不能混入当前轮次硬件失败统计。
7. Host 工具应按源码 Commit、二进制摘要和适配器版本固定；3588 已安装工具不能仅凭文件名认为与源码一致。

## 3. 组织模型

Feature（产品功能域）→ Case（有独立断言的测试项）→ Suite（用例集合）→ Execution（某轮、某设备、某参数下的结果）。Test Bin 是 Case 的执行依赖，不作为 UI 的首要分类。

保留基本功能 set / 特殊场景 set 两大类。基本功能按身份控制、视频帧头、算法模式、ISP、IMU、遥测等功能域展开；特殊场景按长稳、切换压力、流中控制、多机同步、OTA/恢复组织。场景引用已有基础断言，避免复制用例定义。保留 SL-T/M-* 作为来源编号，新增稳定平台 case_id 和 definition_version。

一个用例至少定义：名称、功能域、set、优先级、工具ID/摘要、参数schema、前置条件、超时、断言/阈值、证据要求、清理/恢复、适用芯片/硬件/模式。没有断言的工具入口标记“待适配”，不能选择后假装已经执行了测试。

## 4. 两条状态轴

能力轴：自动化就绪 / 待适配 / 人工测试 / 工具缺口 / 不适用。
执行轴：未测 / 排队 / 运行中 / 通过 / 不通过 / 执行异常 / 阻塞 / 跳过 / 中断。
“待适配”指平台无法可靠自动判定；“不通过”指真正执行后断言不满足；“执行异常”指工具崩溃、超时或结果损坏。历史静态缺口另加标记与来源日期，不代替执行结果。过往通过在新 Patchset 下不能沿用为本轮通过。

## 5. 页面设计

### A. 产品测试覆盖总览

固定顶栏：产品、固件/Commit、比较基线、测试配置、设备/测试台。
汇总：适用测试项数、自动化就绪数、已完成数、通过/不通过/异常/未测数。
主体用可折叠功能矩阵：功能域 > 测试项，每行显示 set、能力状态、本轮结果、关键指标、证据入口、最近有效结果来源。工具未就绪和未测仍然可见。
筛选：只看失败、只看未测、只看待适配、基本功能、特殊场景、优先级。
默认显示所选轮次。若切到同一固件的“最近结果”，每行明确轮次/时间/设备，不将多轮拼接伪装为一次全部通过。

### B. Test Round 配置

保留测试点、构建镜像、测试台步骤。Test Case 选择区按两大 set 分组，支持展开功能域、单项/分组选择和预设集合。每项展示是否可执行、前置条件、预计时间、关键参数。缺工具或额外硬件时显示阻塞原因。
首批预设：基础冒烟（身份/XU/基本出流/IMU）；三流与帧头；30min稳定性。尚未适配的预设保持不可执行，不提供虚假的预计结果。

### C. 轮次执行页

顶部时间线：烧录→启动/身份确认→基本功能→特殊场景→清理→报告。
中间用例矩阵显示每项进度和结果；下方/侧栏展示选中用例的断言表（期望、实测、结论）、原始日志和附件。特殊场景增加 FPS、丢帧率、RTT、温度等有实际数据的趋势图；不填模拟数据。
失败归因分为功能断言失败、前置条件阻塞、工具/基础设施异常。展示恢复是否成功。

## 6. 结果证据与统计

每次执行保存 round_id、case_id/version、attempt、固件SHA、Patchset/Commit、test-bin SHA、adapter version、设备身份、参数/阈值、开始/结束、断言列表、指标、日志附件、恢复结果。

执行覆盖率 = 有最终执行结论的适用项 / 本轮计划适用项（通过+不通过+执行异常）；另列有效判定率（通过+不通过）/本轮计划适用项。
通过率 = 通过/(通过+不通过)，同时强制并列未测、异常、阻塞、跳过数量；分母为0显示“—”。不能用100%通过率掩盖只测一项。
能力覆盖率与执行覆盖率分开。以产品需求确认后的适用范围为分母，不能只拿“已有工具支持的项目”当全部范围。

## 7. 分阶段实施建议

第一步：先上线可浏览能力目录与结果矩阵，所有无有效硬件证据项目显示未测，静态发现和工具缺口单独展示。
第二步：适配只读冒烟：身份/XU/版本/SN、短时出流、IMU；新增烧录后启动及版本/身份确认，避免测试错固件。每个工具补可靠断言与机器可读结果后才解锁。
第三步：模式切换、ISP、三流、帧头、长稳与流中控制时延。先确认 RK3572 阈值与恢复语义。
第四步：多机同步、OTA/A-B、故障注入等特殊场景，加入设备拓扑、独占资源及恢复策略。

本文件为设计草案；尚未实现这些测试执行功能，也未把任何当前产品功能标记为真机通过。

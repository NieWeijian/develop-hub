# 三类测试流程实施记录

2026-09-29

本次新增发布验证与常规定时测试入口，复用现有 TestRound、Controller、用例执行器及证据接口。原有轮次和人工分类记录保留。

## 使用方式

- 快速测试：进入“快速 / 手动测试”，选择产品，点击“快速测试当前模组”；跳过编译烧录。
- 常规定时测试：新建计划，选择产品、Gerrit 分支或 Change、每日时间/时区、测试台、在线模组、用例和参数。默认暂停，勾选启用或保存后点击启用才会自动运行。每次触发冻结实际 commit；Change 链接没有 Patch Set 后缀时解析最新 Patch Set。
- 发布验证：先使用常规轮次完成一次构建，再从已成功构建的轮次固化候选固件。输入独立 RC 名称，镜像复制到 release-candidates/<id> 并校验 SHA。创建全量清单后，分批选择要求并烧录固定候选镜像测试，后续补测不重新编译。也可校验并关联已有轮次的匹配结果。

发布验证和定时执行当前适配 RV1126B；产品原有其他手动流程不变。固件导入本次通过平台已有构建产物完成，不提供任意本地路径输入。

## 结果与清单

每项保存用例/工具定义、参数和修订摘要。展示通过、失败、未测、阻塞、异常、待更新、待定义。参数及工具更新需显式修订并记录操作人和原因，旧证据保留并要求重测。已有轮次的人工通过/失败修正继续在轮次详情操作，发布覆盖显示其有效分类，冻结报告保存当时的分类审计。

六个特殊场景仅占位，不生成假执行命令或判定，不允许执行，也不会从全量清单分母移除。待后续定义测试方法并接入对应自动/人工执行方式后才能完成它们。

同一提交的重新构建不能仅凭 commit 混用；证据要求镜像集合摘要、用例/工具/参数一致，并具备受控烧录、传输校验和启动确认。默认采用最新尝试，后续失败/阻塞不能由旧通过掩盖。所有要求通过才能冻结最终报告，冻结操作不发布固件。

## 调度与恢复

调度器随 Hub API 启停，持久化 TestSchedule 和 ScheduleRun。schedule_id + scheduled_at 唯一约束，创建轮次与关联触发记录同事务提交。重启后复用已创建轮次；派发中断记录阻塞，不悄悄重复烧录。触发超过 5 分钟时跳过，不补跑历史积压。同计划前次未结束则跳过新触发；测试台或共享 SDK 忙时等待。只有代码未变且最近一轮成功时才可按配置跳过。暂停不打断已启动轮次，但取消尚未开始的排队触发。当前配置修改采用暂停旧计划、建立新计划，保留历史。

所有执行入口在启动时检查测试台占用。后端正式部署使用现有单实例服务，不能把本调度器无改造地扩成多个并行 API worker。

## 已接入用例

| 用例 | 判定与恢复 |
| --- | --- |
| FILE-PERSIST-REBOOT | 在 `/userdata/log/qa-<唯一ID>.bin` 写入 4096 字节，先回读校验，然后 reboot，观察 USB 消失及同 CPU 序列号/端口/固件重连，再校验 SHA-256。现有工具没有删除命令，测试文件保留并明确记录路径及大小。 |
| FILE-MODULE-LOG | get-log 保存日志尾部，枚举并下载 lasted.log；尾部非空、完整文件非空。活动日志持续变化，不以下载前瞬时长度判定失败。大于 60000 字节时阻塞，不将尾部当作完整日志。 |
| FILE-ARCHIVE-LOG | 枚举 archived，下载所有 .gz，逐个比较长度并验证 gzip CRC/解压完整性。没有归档或存在超限文件时阻塞，不修改或清理日志。 |
| FACTORY-SN | 备份原标定文件与 SN，进入 calib，写唯一测试 SN，立即回读，reboot 后再次回读，切到 rgb+depth，验证 SN 并抓图。最后回 calib 恢复原标定文件，reboot 后核验原文件 SHA/SN，再进入 rgb+depth。 |
| FACTORY-BOARD-SN | 备份上下板 SN，在 calib 先改上板、确认下板不变，再改下板，重启核验；rgb+depth 核验 SN 与抓图。结束恢复上下板原值，重启核验，最终 rgb+depth。原值为空/不可写时提前阻塞。 |
| FACTORY-CALIB | 备份原活动标定文件与 SN，进入 calib，通过 set-calib 上传用户夹具，file-get 回读 SHA，并核验 YAML SN 的读取。恢复原文件，重启核验 SHA/SN，恢复原设备模式。不把上传成功宣称为标定精度通过。 |

在可能已发生写入但 CLI 应答丢失时，也进入恢复流程。恢复失败标为执行异常并阻止后续用例。每次重启必须观察 USB 消失与同一设备重连，不能立即读取旧进程假装重启成功。CPU serial 不依赖被改写的模组 SN。

文件下载新增前端逐文件入口，Hub 仅提供结果清单声明且 SHA-256/长度校验通过的附件。图片展示保持原样。

## 不接入与接口缺口

- 移除文件断电持久化、通用参数持久化。reboot 不等价于断电测试。
- 老化触发移到特殊场景：当前 RkLunch.sh 通过 extcon 检测 DCP=1 进入老化，SDP/CDP=1 进入正常工作。host 端口解绑、禁用、掉电不能证明 DCP 识别；没有已验证的可编程 DCP 工装，所以本次不操作端口。
- 老化日志专项待工装接入后检查：老化启动、周期 telemetry（温度、帧率等）、判定、结束/失败日志；不能用 set-ft-aging 写标志代替真实老化。
- 冻结的 file-get/file-put 单文件上限 60000 字节，固件需要补充分段下载/文件校验能力才能覆盖较大日志；Hub 不绕过 tools 直接进入模组读取。
- set-board-sn 不接受空字符串，无法恢复原空值；需要固件补充清空/恢复接口后再覆盖空 SN 出厂模组。
- 文件删除接口缺失：持久化测试当前保留独立 4 KiB 文件，后续可接入删除与清理验证。

## 新用例执行契约

每个正式可执行定义至少包含：

- `code/definition_version/scenario/priority`：稳定身份、定义版本和分类。
- `applicability`：产品、硬件、固件能力、模式、工装；不适用必须记录依据。
- `parameters/schema/matrix`：支持分辨率和模式来自对应固件能力，不写死为“所有设备相同”。保存展开后的实例及随机种子。
- `preconditions/resources`：设备身份、USB 拓扑、测试台就绪、独占资源、时间基准、标定靶/继电器等。
- `adapter/tool_sha/timeout`：版本化执行器、匹配源码的工具和可靠超时。
- `threshold_profile`：产品/硬件/模式专属的版本化阈值。未确认阈值时记录测量值并标阻塞或仅采集，不能猜一个数宣称 PASS。
- `assertions`：期望、实测、单位、比较方式、容差、判定、数据来源。
- `evidence`：XU 收发、进程退出码、逐帧/逐样本指标、原始帧、曲线数据、日志与附件摘要。
- `recovery`：原值备份、恢复与回读；恢复失败停止依赖同一状态的后续实例。

能力状态与执行状态分开：待适配/可自动执行/人工/缺工具；未测/运行中/通过/不通过/异常/阻塞/跳过/中断。尚未测量的曲线不填示例数据。

## 指标与判定口径

- FPS = 有效帧数 / 明确定义的有效窗口时长；预热窗口、起止帧规则写进定义。短时与长稳均保留时间序列，不能只看总平均。
- 丢帧率按设备序号推算缺口，明确计数器回绕/重置规则；主机丢包、设备缺帧、重复和乱序分别报告。没有可靠序号时不能称为已测丢帧率。
- 抖动记录帧间隔与目标间隔的偏差分布；p50/p95/p99、最大值和异常时间段同时保留。
- 主机接收、算法完成和曝光时间属于不同事件。跨时钟延时先校时并估计误差；光学端到端延时需要外部参考，不能把 ioctl RTT 当成视频延时。
- RGB-IMU 按曝光时间配对样本，记录偏差、覆盖率、漂移；运动效果验证与时间戳对齐分成独立断言。
- 空洞率/闪烁须固定靶、距离、光照、ROI 和无效像素定义；保存原始数据以便复判，不以预览肉眼观感自动报通过。
- SN/标定/持久化测试在专用设备与隔离路径执行；完成立即回读、重启回读、断电回读是三个不同验证层级。
- 老化“写结果标记”与“完成真实老化周期”分开。完整周期由产品配置给出；不把历史知识里的阈值直接当成当前量产验收标准。

## 源码与完整流水线设计

1. 环境预检：175→3588 SSH，目录/磁盘、工具与执行器版本、Controller、DFU 权限、USB 拓扑/速率、设备身份、所需工装；失败不排编译。
2. 源码来源统一为 `source.kind = gerrit | local_commit`。Gerrit 冻结 Change/PS/ref/完整 commit/subject；本地来源仅允许已登记应用仓库，指定 ref 后解析完整 commit。未提交改动需显式生成可追踪补丁快照或先提交，不能悄悄混入构建。
3. 获取 SDK 独占锁，冻结应用和 SDK 基线、工具源码、Board Config、用例版本及阈值。UI 主显示 comment/subject，完整哈希保存在报告证据。
4. 构建：应用强制重配和 git_build_id 核验，再构建 oem/system/boot；退出码、产物刷新、摘要都通过才交付。
5. 交付：配置/镜像/用例包→3588 独占任务目录，摘要复核后发布 READY。
6. 烧录：3588 验证同一 CPU/端口，写另一 A/B 槽，保留标定和用户数据，记录烧写次数用于追溯，不设置次数上限。
7. 启动：检查目标槽、本轮 commit 与设备身份，失败禁止执行功能用例。
8. 场景：就绪项按计划生成实例、串行执行有状态项目；每项独立保存断言和恢复结论。最后输出逐用例报告和未覆盖原因。

本地来源 API 与构建适配尚未在本次改版实现；不能把前端产品中的本地 SDK 路径当成这个功能已完成。

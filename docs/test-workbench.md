# RMSL321 测试台操作规则

## 当前页面与操作入口（2026-10-08）

测试台主导航按任务组织：开始测试、测试记录、发布验证、定时回归、配置管理。

- **开始测试**：先选择产品，再选择“测试当前固件”“编译烧录测试”或“仅构建交付”。当前固件测试跳过 SDK 构建与烧录，不要求基线构建通过；其余两种模式必须具备有效产品基线，并显式选定 Gerrit Patch Set。
- **配置测试**：唯一产品和已启用测试台自动选中；需要设备的模式自动检测模组，只有一台时自动选中。启动仍须明确点击执行按钮。用例按功能分组，支持搜索、分组选择与清空。出流质量测试默认 5 小时，配置前应确认时长。
- **仅构建交付**：选择版本和接收测试台即可，不需要选择设备、用例。终点为“交付完成 · 未测试”。
- **测试记录**：按产品、来源和状态筛选；轮次详情突出自动结论，人工复核仅在存在修正时另外说明，保留原始证据。
- **发布验证**：从验证计划列表进入覆盖详情。新建计划时选择已有候选固件，或从成功构建轮次先固化新候选；每次补测复用固定镜像。参数修订、关联历史证据与冻结报告位于进阶操作中。
- **定时回归**：选择代码来源、每日时间、设备、用例和参数；默认保存为暂停状态，启用后自动产生轮次。
- **配置管理**：集中维护产品与基线、用例库、测试台节点。场景扩充规划与执行定义折叠展示。

发布覆盖在运行时按 Controller 单项状态显示等待、运行中、已完成待确认、阻塞；已完成待确认不算通过，必须等待整轮结束及完整证据校验。未定义的特殊场景仍保留在覆盖分母中。冻结报告不发布固件。

每个轮次固定当时的产品、固件来源、镜像摘要、设备身份、用例/工具定义与参数。Gerrit 列表按更新排序，不等于提交链顺序，需选择所需提交链的顶端。失败后建立新轮次，保留旧记录。

## 执行顺序与门禁

1. **源码**：校验 Gerrit Ref 与完整 Commit，fetch 后再次确认 HEAD。应用仓库有 tracked/staged 改动时拒绝执行；操作员应先处理或 stash。未跟踪文件不自动删除。
2. **构建**：独占已注册 SDK。RMSL321 V2.0 使用 RV1126B 的 `./build.sh lunch` 和 `./build.sh all`；不生成额外发布归档。RK3572 保持独立适配器。构建退出码、生成的应用版本和本轮镜像刷新检查必须全部通过。
3. **交付**：冻结镜像并复核复制后 SHA-256，上传测试配置与镜像，测试台再次校验摘要，最后发布 READY。半份配置不能触发执行。
4. **烧录前检查**：RMSL321 必须处于正常 UVC 模式。CPU 序列号和 USB 端口必须仍匹配；版本必须能确定当前 A/B 槽；控制程序、执行器、全部用例及输入文件摘要必须匹配。
5. **烧录**：通过 XU 进入 DFU，仅向另一槽写入 oem/system/boot。标定、userdata、env、bootloader 不属于本适配器写入列表。记录逐分区退出码、下载完成证据和烧写计数。烧写计数仅用于追溯，不限制后续烧录次数。
6. **启动确认**：等待同一物理端口重新出现；复核 CPU 序列号、目标启动槽以及本轮 Gerrit Commit。旧版本、错误设备、启动超时均阻止用例执行。
7. **测试**：按计划顺序运行用例，保存期望值、实测值、断言、原始 XU ioctl 收发、标准输出和错误日志。参数恢复失败阻止后续用例。
8. **报告**：仅当所有所选用例有完整通过断言、烧录成功且启动身份确认通过时，轮次显示“测试通过”。可下载完整 JSON 报告。

## 最初接入的基础用例（历史说明）

| 用例 | 判断标准 | 恢复行为 |
| --- | --- | --- |
| BASIC-VERSION | 运行固件版本包含本轮 commit；有真实 XU 证据 | 无状态修改 |
| BASIC-FOV-READ | 读取值属于设备支持列表 | 无状态修改 |
| BASIC-FOV-WRITE | 写入受支持 FOV 并回读一致 | 恢复原值并复核；恢复失败记异常 |
| BASIC-FILE-ROUNDTRIP | 1024 字节输入与回读文件长度、SHA-256 均一致 | 临时文件在模组 /tmp，重启清除；报告明确记录 |

以上仅是基础功能回归，不代表出流性能、图像质量、IMU、稳定性或完整量产验收。新增用例必须有版本化适配器、独立断言与证据；仅登记一条命令不等于具备自动化测试能力。

## 状态与重试

- 编译失败：未烧录，查看命令退出码及日志。
- 阻塞/异常：检查具体前置条件、连接、身份或执行器错误；不算功能断言失败，也不算通过。
- 测试不通过：至少一项断言失败或发生执行异常；查看逐项结果。
- 烧录完成：仅用于已有的 RK3572 烧录范围；不能替代测试通过。
- 失败后创建新轮次，不覆盖已有证据，不对旧 READY 自动重刷。
- API 重启后的进行中构建标记中断；独立运行的测试台任务通过原任务 ID 重新接收结果。烧录期间勿重启测试台 Controller 或拔线。
- 历史展示编号不复用，因此清理数据库后编号可以继续递增。

## 平台页面验收规则

验收必须从页面操作发起，经过正常后端工作流、测试台 Controller，到页面结果和下载报告。直接调 API 创建任务、在终端执行模组命令只能算诊断或后端验证，不能替代平台验收。

- 用例库的“同步内置用例”加入缺失的已适配用例，重复同步不改 ID、分类和旧记录。
- 同一产品重复登记相同 Change / PS，重新核验 Ref / Commit 后复用并选中已有测试点。
- RMSL321 完整轮次在创建前检查测试台连接、Controller 服务、执行器和用例包版本、DFU 权限；未通过不排入构建。
- 用例确认区的顺序就是最终保存和执行的顺序。
- 仅构建交付与完整验证使用相同的板级镜像规则，但仅交付不能标为测试通过。
- 产品和轮次详情写入页面 URL，刷新后可返回对应记录。未提交的表单刷新后回到产品。
